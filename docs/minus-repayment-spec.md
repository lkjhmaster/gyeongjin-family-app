# 마이너스 변제 기능 구현 기준 (2026-10-12)

상태: 설계 확정, 실제 코드 반영 전. 기존 잔고를 변경하지 않는다.

## 입력
- 자유/카드용돈의 거래 구분: 지출, 수입, 마이너스 변제.
- 변제액은 마이너스 원금 감소분이다. 카드로 자유성격 채무를 변제할 때 총 차감액은 변제액 + 수수료(현재 40%).
- 부모 승인 전 모든 관련 잔고 불변. 자녀 요청은 서버에 영구 보관해야 한다.

## 출처 추적 및 우회 방지
- 마이너스 지출은 각각 고유 채무 ID, 소비 성격(free/card), 미변제 원금, 승인자 기록을 가진다.
- 소비 성격은 부모가 승인하며 자녀가 단독 확정할 수 없다.
- 카드→자유 성격의 채무 변제는 기존 카드→자유 환전 수수료율을 적용한다.
- 여러 채무를 혼합 변제하면 각 채무별 부분 변제액과 수수료를 계산하고 기록한다.
- 출처 불명확한 기존 마이너스 채무는 자동 무수수료 처리하지 않고 부모 분류를 요구한다.

## 승인과 정합성
- 변제 요청에는 대상 채무 ID와 부분변제액, 수수료, 총 차감액, 출처 용돈, 요청자, 승인자를 저장한다.
- 승인 트랜잭션에서 용돈 잔고/마이너스 미변제액을 재검증하고 원장 차감·채무 감소·감사기록을 원자적으로 반영한다.
- 고유 요청 ID를 통해 중복 승인을 차단한다.
- 부모 거절 시 잔고 불변, 요청/거절 이력 보존.
- 이미 수동 처리된 과거 건은 자동 재반영하지 않는다.

## 구현 전 확인한 기존 코드 결함
- index.html 의 allowanceChild/saveAllowance/reviewAllowance는 로컬 원장과 가족상태 동기화 기반이며, D1 서버 승인 트랜잭션이 아니다.
- 따라서 단순히 거래 유형 옵션만 추가하면 승인 누락, 중복 변제, 원장 불일치 위험이 있다.
- 반드시 서버 원장 및 승인 API를 함께 구현한 후 배포한다.

## 검증 시나리오
1. 자유→마이너스 3,000원 변제: 자유 -3,000, 채무 -3,000.
2. 카드→카드성격 채무 3,000원 변제: 카드 -3,000, 채무 -3,000.
3. 카드→자유성격 채무 3,000원 변제: 카드 -4,200, 채무 -3,000.
4. 미승인/거절 요청: 모든 잔고 불변.
5. 이중 승인/동시 승인: 한 번만 반영.
6. 출처 미분류 채무: 승인 차단 후 부모 분류.
7. 잔고 부족/채무 초과/날짜 변경/다른 기기 승인: 안전하게 거절 또는 지속 표시.
