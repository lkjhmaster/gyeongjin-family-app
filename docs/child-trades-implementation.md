# 자녀 간 거래 구현·검증 기록

기준: `77d7adf409b31b9fad88cb0ca19655be39285d63`. 모바일 실기기 검증 제외.

## 구현

- 대여·물품·상환 신청, 서버 계산 견적, 요청 재전송 방지, 당사자 동의와 부모 승인.
- 물품 승인 시 출금 대신 예약. 두 당사자의 전달 확인 후 단 한 번 정산.
- 일부·전액 상환: 실수령액만 원금 감소. 미상환 차입이 있으면 다른 상대방에게도 신규 차입 금지.
- 마이너스 수령은 기존 사용 건을 지정한 변제로 처리. 기존 출처별 수수료와 원장 연결 보존.
- 전액·부분 환불은 누적 비례 수수료를 복원하는 참조 분개 추가. 원거래 수정·삭제 금지.
- 승인 후 취소·환불·예약 조건 변경·분쟁 해제에는 양측 협의와 부모 승인 필요.
- 조건 변경은 기존 동의를 무효화. 정산된 대여 조건은 반환 후 재신청.
- 회수 잔액 부족은 자동 마이너스 없이 부모 조정 상태로 전환.
- 통합 승인함, 거래 상세, 전체 감사 이력, 용돈 달력의 거래 상세 연결, 연체 알림.

## 원자성·기존 데이터

모든 거래 쓰기는 단일 D1 batch로 처리한다. 첫 CHECK assertion은 조회한 가족 용돈·한도, 거래·대여·예약·변경·동의 상태를 재검증한다. 다른 쓰기가 먼저 일어나면 전체 batch가 롤백된다. 확정 분개와 감사 이력은 데이터베이스 트리거로 수정·삭제를 차단한다. 예약금은 일반 용돈 API와 정기 처리에도 동일한 보호 트리거가 적용된다.

정기 용돈도 월별 처리 주장과 가계부·용돈·감사 기록을 하나의 batch로 반영한다. 충돌 시 재조회하며 이미 처리한 월을 중복 지급하지 않는다. 기존 테이블 삭제·초기화·잔액 재계산 마이그레이션은 없다. 기존 거래에는 메타데이터만 추가한다.

## 실제 실행 검증

- Node test runner 34개 테스트 통과. 순수 도메인 테스트 내부 assertion도 별도 실행.
- 실제 SQLite에서 승인·정산·상환·환불, 보유 예약금, 권한·가족 격리, 마이너스 변제 복원, 재동의, 동시 변경과 중간 실패 롤백 검증.
- 마이그레이션 재적용 후 기존 분개·원장 보존 검증.
- 정기 용돈 충돌 재시도·월별 1회 반영과 거래 내역 보존 검증.
- 기존 마이너스 변제 취소·통합결제 회귀 및 인라인 문법·Worker 문법 검사 통과.
- 실제 데스크톱 Edge: 견적 → 신청 → 상대 동의 → 통합 부모 승인 → 일부 상환 → 양측 물품 전달·정산. 사용자 입력 escaping, 스크립트 오류, 가로 넘침 점검.

## 배포 확인

CI는 실제 브라우저 테스트와 Cloudflare 번들 빌드까지 수행한다. 배포는 성공한 CI의 정확한 커밋만 사용한다. 기존 복구 시점 확인 명령의 잘못된 `--remote` 옵션을 수정했고, 기존 D1 설정 파일을 명시한다. 복구 시점 확인 → additive 마이그레이션 → 스키마 확인 → API 배포 → 실제 API 릴리스·D1 확인 → UI 배포·실제 HTML 확인 순서다.

실제 CI/배포 성공 여부는 Actions 실행 결과와 서비스의 `release`, `childTradeSchema`로 확인해야 하며, 이 문서만으로 성공을 주장하지 않는다. 모바일 실기기 검증은 사용자의 별도 단계다.
